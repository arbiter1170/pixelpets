# Walklings smoke tests

Small browser checks so a later change can show the game still boots on a phone width. Players never load this folder. There is no GitHub Actions workflow yet: run the suite locally. A new spec also gets a row in this file, and the status docs follow `.cursor/skills/walklings-docs/SKILL.md`. The Oct 14 documentation audit added no spec. Recording the town-board calls the same day added no spec. TB-1 is covered by `tests/town_board.spec.js`. Scoping modern and arcade controls (Q26) added no spec. `tests/controls.spec.js` covers it: arcade on an old save, every modern button, switching both ways, and the joystick.

## How to run

From a clean clone, in the repo root:

```
npm install
npx playwright install chromium
npm test
```

`npm test` runs `python3 tools/bump_build.py --check` (must exit 0) and then Playwright. `npm run test:agent` runs that same build check, then `node tools/rtdb_rules_test.js` against a local Realtime Database emulator, then Playwright. The rules step and `tests/play_together.spec.js` talk only to `127.0.0.1` (auth 9099, Firestore 8180, database 9000 in `firebase.json`). The browser maps the live Firebase hosts to an address that does not resolve, and `cloud.js` ignores the live config while `navigator.webdriver` is set, so the suite never signs in or writes to project `walklings-4cc89`. The pinned SDK host stays reachable so `?cloud=emu` can load it. Chromium only, one width at a time, against a local static server (`python3 -m http.server`, port 8080). Set `PP_URL` to point at another origin instead, for example the live site:

```
PP_URL=https://arbiter1170.github.io/pixelpets/ npm test
```

When `PP_URL` is set, the config does not start a server. `PP_PORT` changes the local port.

Projects (CSS pixels, mobile Chromium: `isMobile`, `hasTouch`):

| Project | Viewport | deviceScaleFactor |
|---|---|---|
| 320 | 320×568 | 2 |
| 375 | 375×667 | 2 |
| 390 | 390×844 | 3 |

Screenshots are written to `test-results/screenshots/` (gitignored): the walk screen with the QUEST button (`walk-quest-<width>.png`), the open next-step panel (`quest-panel-<width>.png`), and from Build 2 the STANDING tab (`standing-tab-<width>.png`), the quest panel with the designer copy on each side (`quest-panel-keepers-<width>.png`, `quest-panel-glimmer-<width>.png`) and the d-pad icons (`quest-icon-<width>.png`). Rook's Crossroads adds `rc-rook-dialog-<width>.png`, `rc-crate-<width>.png`, and `rc-switch-confirm-<width>.png`. Reference copies of the Build 2 set live in `screenshots/standing/`.

Shared helpers are in `tests/helpers.js`: `starterSave()` (the v2 seed used below), `installSave(page, save)`, `gotoGame(page, query)`, `trackErrors(test, expect)` (the console-error assertion), `boxesOverlap`, `shot(page, name)`, `withOverlay(page, overlay, key)` (adds a fixture `data/detail_*.json` overlay to `MAPDATA` before boot; call it before `gotoGame`), and `playScene(page, choices, onChoice)` (presses Space through plain lines and clicks `#sbChoices` buttons by label once `PixelPets.optionsReady` is true; returns the prompts it saw).

A console message of type `error`, or any uncaught page error, fails the test.
